## 기본 원칙

1. 숫자는 값만 전달하지 않고 단위, `MetricQuality`, source를 함께 유지한다.
2. source가 없거나 parse가 불확실하면 0을 만들지 않고 `N/A`/`UNAVAILABLE`로 둔다.
3. exact DPU underrun은 검증된 vendor 또는 allowlisted kernel counter만 사용한다.
4. missed frame, Choreographer, SurfaceFlinger miss와 producer shortfall은 proxy다.
5. source/encoding/quality가 바뀐 counter interval을 이어 붙이지 않는다.
6. estimated traffic과 measured bus utilization은 서로 다른 metric이다.
7. non-finite 값은 HUD에서 `N/A`, JSON에서 `null`이다.

## MetricQuality

| Quality | 의미 |
|---|---|
| `HARDWARE_COUNTER` | versioned vendor service가 반환한 검증된 HW 값 |
| `KERNEL` | typed/allowlisted read-only kernel ABI |
| `SYSTEM_SERVICE` | Android framework/system service |
| `MEASURED` | 앱이 시간 구간에서 직접 계산 |
| `ESTIMATED` | 명시된 선형 모델 |
| `PROXY` | 목표 현상의 간접 신호 |
| `UNAVAILABLE` | 값 또는 신뢰 가능한 provenance 없음 |

quality 순서는 “더 큰 enum 값이 더 정확하다”는 일반 우선순위가 아니다. metric별 source
선택 규칙을 적용한다.

## Metric matrix

| Metric | 단위 | 우선 source | Fallback / quality | 주의 |
|---|---:|---|---|---|
| 전체 CPU | `%` | `HardwarePropertiesManager` | `/proc/stat` measured | source 전환 interval은 N/A |
| app CPU | `%` | `Process.getElapsedCpuTime` measured | 없음 | multi-core이면 100% 초과 가능 |
| memory used | `%` | `ActivityManager.MemoryInfo` | 없음 | total/available 유효 범위 검증 |
| memory available | `MB` | `ActivityManager` | 없음 | graphics budget 입력 |
| app PSS | `MB` | `Debug.getPss` measured | 없음 | process resident estimate |
| display refresh | `Hz` | `Display.getRefreshRate` | 없음 | 요청값과 실제값을 구분 |
| produced FPS | `fps` | producer callback interval | baseline 전 N/A | aggregate fidelity와 별개 |
| exact underrun | count | vendor v1 | configured kernel counter | monotonic continuity 필수 |
| suspected underrun | count | `FrameTracker` | 없음 | Choreographer deadline miss proxy |
| GPU busy | `%` | vendor v1 | typed kernel GPU ABI | encoding과 source 결속 |
| GPU frequency | `MHz` | vendor API v2 Hz | typed kernel frequency | unit 명시 필수 |
| bus busy | `%` | vendor v1 | typed devfreq/kernel ABI | generated traffic과 합치지 않음 |
| generated bandwidth | `Gbps` | memory worker copied bytes/real interval | baseline 전 N/A | app memory load만 측정 |
| DPU busy | `%` | vendor v1 | typed kernel ABI | 없으면 N/A |
| DPU frequency | `MHz` | vendor API v2 Hz | explicit `dpu_frequency_hz` | write/lock 금지 |
| HWC DEVICE/CLIENT | layer count | 동일 vendor snapshot pair | eligible SF snapshot | complete atomic pair만 선택 |
| SF HWC/GPU missed | count | SurfaceFlinger diagnostic | 없음 | proxy, exact underrun 아님 |
| thermal | Android status | `PowerManager` | 없음 | CRITICAL 이상은 safety event |

sample nominal cadence는 controller monitor 1초, watchdog 500 ms다. 수집이 느릴 때 rate는
실제 monotonic interval을 사용하며 호출 횟수로 1초를 가정하지 않는다.

## Telemetry transaction

`SystemMonitor`는 single-flight lane에서 다음을 한 번의 sample로 수집한다.

1. CPU interval 시작과 source
2. app CPU와 memory
3. display refresh
4. SurfaceFlinger probe policy
5. vendor snapshot
6. kernel snapshot
7. produced frame와 generated byte interval
8. thermal/low-memory/Battery Saver/vendor session
9. 모든 read가 끝난 completion timestamp

`TelemetrySnapshot.monotonicMs`는 마지막 evidence read가 끝난 시각이다. CPU interval
시작 시각과 같지 않다. accepted single-flight operation은 4초 operation timeout과
다음 500 ms watchdog tick까지의 bounded deadline만 보호된다.

active typed target의 periodic sample은 latest-wins try-lock/drop으로 처리한다. forced
sample과 waiter backlog를 경쟁시키지 않는다.

## Exact underrun counter

### Source

우선순위는 다음과 같다.

1. 현재 vendor service session의 non-negative `underrunCount`
2. 제품 config 또는 검증된 allowlist의 non-negative kernel monotonic counter
3. 없음: `N/A`

platform signing만으로 counter 접근이 생긴다고 가정하지 않는다.

### Baseline과 continuity

- warm-up과 모든 producer first-buffer readiness 뒤 serialized fresh sample로 baseline을
  설정한다.
- source와 quality는 baseline에 결속된다.
- 현재 값은 baseline과 지금까지의 highest보다 작아질 수 없다.
- null, source/quality 변경, reset/regress, telemetry gap은 continuity를 무효화한다.
- 이전 run에서 시작한 in-flight sample을 새 baseline으로 사용하지 않는다.
- 양의 delta evidence는 보존하지만 exact 0은 끝까지 continuity가 있어야 한다.

정상 종료에서는 physical producer의 최종 teardown 뒤 serialized fresh terminal sample을
얻어야 한다. 이 sample이 실패하면 exact continuity를 무효화한다.

### Verdict 우선순위

| Evidence | 기본 verdict |
|---|---|
| reliable exact delta > 0 | `UNDERRUN_DETECTED` |
| reliable exact delta == 0 | `CLEAN` |
| exact unavailable, proxy delta > 0 | `SUSPECTED_PROXY` |
| exact unavailable, proxy delta == 0 | `INCONCLUSIVE` |
| counter regress/invalid negative case | `INCONCLUSIVE` |

reliable exact가 있으면 proxy보다 우선한다. exact 0인데 proxy가 증가한 경우 verdict를
`SUSPECTED_PROXY`로 내리지 않고 `CLEAN`을 유지하며 proxy를 event로 보존한다.

typed HWC coverage 실패 또는 producer rate shortfall은 exact positive underrun이 없는
경우 결과를 `INCONCLUSIVE`로 내릴 수 있다. `UNSUPPORTED`와 safety/cleanup
`ABORTED`는 별도의 terminal verdict다.

## Proxy evidence

다음은 underrun exact counter가 아니다.

- `FrameTracker`의 Choreographer deadline miss
- SurfaceFlinger HWC/GPU missed frame
- producer heartbeat/stall
- requested FPS와 measured frame fidelity 차이
- display refresh request 불일치

proxy는 문제가 있을 가능성을 보여 주지만 DPU underrun 원인을 단독으로 증명하지 않는다.

## HWC DEVICE/CLIENT evidence

complete DEVICE/CLIENT pair만 사용한다.

- device와 client가 둘 다 non-negative
- 동일 source, 동일 quality, 동일 transaction
- evidence completion timestamp와 age 보존
- 최대 age 2.5초
- 허용 quality: vendor `HARDWARE_COUNTER` 또는 eligible SurfaceFlinger
  `SYSTEM_SERVICE`

현재 vendor session의 complete pair가 검증되면 active typed sample에서 새
SurfaceFlinger process를 만들지 않고 같은 telemetry transaction의 vendor pair를
사용한다. snapshot timeout은 Binder disconnect가 아니다. 실제 service session이
바뀌면 pair를 폐기한다.

HUD의 `RAW MATCH`, `RAW WAIT`, `RAW N/A`는 현재 raw pair의 보조 해석이다. controller는
target activation, distinct sample 수, topology revision과 phase coverage를 별도로
검증한다.

Process-session HWC capacity 결과도 위 complete-pair 규칙을 따른다. Requested 20과
safety-approved actual candidate를 구분하고, source/quality/evidence time이 불완전하면
0이 아니라 terminal `UNAVAILABLE`을 보존한다. 이 값과 calibration 중 얻은
SurfaceFlinger cache는 typed phase evidence가 아니며 matching topology의 advisory다.
상세 topology, deadline, probe serialization, display scope, cleanup과 event는
[HWC capacity calibration](HWC_CAPACITY_CALIBRATION.md)이 authority다.

## GPU source와 Xclipse

generic 경로보다 architecture-specific typed ABI를 먼저 검사한다.

### Qualcomm

- `/sys/class/kgsl/kgsl-3d0/gpu_busy_percentage`: direct percent
- `/sys/class/kgsl/kgsl-3d0/gpubusy`: 한 read의 busy/total window

KGSL `gpubusy`를 cumulative delta로 해석하지 않는다.

### Samsung Exynos Xclipse

Xclipse는 Mali가 아니라 AMD RDNA 기반 Samsung GPU다. 기본 portable candidate는
`/sys/class/drm/card0/device/gpu_busy_percent` direct-percent ABI다. 다른 DRM minor나
제품 전용 경로는 typed config로 명시한다.

### MediaTek

`/sys/module/ged/parameters/gpu_loading`은 direct percent 후보다. GED debugfs/hal
format은 기본 탐색하지 않고 explicit config에서만 사용한다.

### Legacy Mali와 compatibility

legacy non-Xclipse Exynos Mali와 `/sys/kernel/gpu/gpu_busy` compatibility 후보는
architecture-specific ABI 뒤에서만 검사한다. 주소 기반 platform directory를
무작위로 탐색하지 않는다.

명시적인 GPU path/format이 실패하면 generic fallback으로 숨기지 않는다. cumulative
encoding은 read gap 뒤 baseline을 폐기한다.

## DPU, bus와 frequency

- DPU/bus busy는 0..100 범위의 direct percent 또는 source에 결속된 busy/total
  cumulative delta만 허용한다.
- DPU frequency kernel route는 제품이 지정한 read-only Hz path
  `dpu_frequency_hz`만 허용한다.
- vendor GPU/DPU frequency는 AIDL API v2 getter이며 `apiVersion >= 2`, same-session과
  범위 검증을 통과해야 한다.
- optional v2 failure는 같은 session의 v1 snapshot을 지우지 않는다.
- 앱은 DPU/GPU/DRAM frequency, governor나 devfreq에 쓰지 않는다.

## Producer fidelity

expected aggregate frame은 active measured time에 다음을 적분한다.

```text
producer FPS × committed physical producer count × active interval
```

topology pending, transient producer recovery와 안전 control 구간은 frame budget에서
제외한다. callback은 generation과 physical producer ID가 일치해야 한다.

- `FLATTENED_TEXTURE` physical count는 1
- expected aggregate가 30 frame 이상이고 actual이 70% 미만이면
  `PRODUCER_RATE_SHORTFALL`
- verified exact delta가 양수가 아니면 해당 run은 `INCONCLUSIVE`

`topologyMissed`, `teardownFailed`, `teardownCompleted`는 현재 generation의 activation,
producer readiness, geometry revision/profile/coverage와 typed HWC evidence를
fail-closed로 무효화한다. Miss/failure는 새 generation 없이는 회복하지 않는다. 정상
teardown 뒤 reattach도 새 topology와 geometry acknowledgment를 publish하고 activation한
뒤 모든 producer의 fresh first buffer와 fresh HWC observation을 다시 수집해야 한다.
이전 sample이나 coverage는 새 target에 승계하지 않는다.

HUD의 expected count는 topology unpublished/pending 또는 process lease 중에는 0,
`—P` 의미로 표시한다. committed frame-budget count와 UI projection을 혼동하지 않는다.

## Estimated layer traffic

`LayerTrafficEstimator`는 linear full-buffer model이다.

```text
producer write = Σ(producer buffer bytes) × producer FPS
DPU read       = Σ(direct scanout buffer bytes + client target bytes) × display Hz
```

주요 전제:

- RGBA/Canvas/Texture/GL output은 4 B/px
- RGB565 producer는 2 B/px
- decoder는 selected media metadata에서 검증된 B/px만 사용
- decoder B/px는 finite, 0 초과, 16 이하
- format/size가 불명확하면 aggregate는 N/A
- `FLATTENED_TEXTURE`는 display-sized RGBA producer 하나
- mixed Texture output은 display-sized RGBA client target read를 추가
- SBWC compression ratio는 제외

tiling, cache, crop/occlusion, partial update, source/destination scaling, HWC client-target
fallback의 실제 bandwidth와 vendor compression metadata는 포함하지 않는다.

`LayerSizeProfile`이 small/mixed destination footprint를 선택해도 source buffer allocation과
producer full-buffer write가 자동으로 작아졌다고 계산하지 않는다.

HUD용 destination footprint는 일반 phase에서 `LayerSizeProfile` base scale만 사용하는
별도 geometry estimate다.

```text
screen equivalents = Σ(widthScale × heightScale)
average percent     = screen equivalents × 100 / physical producer count
```

이 값은 `MotionProfile` scale, overlap, clipping/crop, rotation과 off-screen loss를
제외한 base-profile footprint다. 단 `CAPACITY_TILES`는 명시적인 scope 예외로 실제
non-overlap crop union을 합계 1 screen-equivalent, 평균 `100 / physical producer
count`%로 투영한다. HUD는 estimator가 반환한 `BASE PROFILE` 또는
`CAPACITY TILE CROP UNION` scope를 그대로 표시한다. `FLATTENED_TEXTURE`는 physical
producer 1개를 사용한다. 값은 full-buffer DPU read/producer write나 measured bus
utilization에서 빼지 않는다.

### Layer geometry apply evidence

Destination geometry evidence는 hardware metric이 아니라 generation-scoped app control
evidence다. Base geometry가 실제 child View에 적용될 때 requested revision/profile을
기록하고, 두 번의 후속 `Choreographer` callback/traversal opportunity가 지난 matching
revision/profile만 applied로 인정한다. Pending revision 동안 last-applied base-size
fraction을 유지하고 controller clock은 latest desired를 계속 갱신한다. ACK 뒤에는
중간 fraction backlog가 아니라 최신 desired만 다음 revision 후보가 된다. Gradual
revision key는 origin/mid/exact endpoint 3개, abrupt key는 8개 step이다. Producer
activation과 typed HWC target arm은 latest requested/applied revision 및 target profile
일치를 요구한다. 이 값으로 HWC DEVICE/CLIENT 또는 physical plane 적용을 추론하지
않는다.

Dynamic profile coverage는 applied acknowledgment만 누적한다.

- `GRADUAL_SMALL_TO_FULL`: origin, midpoint, endpoint
- `ABRUPT_SMALL_FULL`: bounded 8 step 전체

Prior explicit static origin이 없는 preparation은 `SMALL_UNIFORM`을 사용하며, prior
full/small/mixed origin이 있으면 그 static measured edge를 보존한다. 같은 producer
generation에서 `SMALL_UNIFORM`의 matching applied acknowledgment가 확인되고 실제
geometry가 dynamic fraction-zero와 같으면 controller는 target dynamic profile의 origin
coverage bit 하나를 equivalent evidence로 seed한다. 이는 active profile 자체의 apply
증거나 midpoint/endpoint/abrupt의 다른 step coverage를 대체하지 않는다. Phase 끝에
required mask가 없으면
`LAYER_SIZE_COVERAGE_MISSING`과 `INCONCLUSIVE`, 모두 있으면 `LAYER_SIZE_COVERAGE`
event를 남긴다.

`generatedBandwidth`는 memory load worker가 실제 복사한 byte를 sample interval로 나눈
`MEASURED` 값이다. 위 estimated display traffic이나 hardware bus busy와 합산하지 않는다.

## Peak와 graph gap

run peak는 유효 범위 안에서 동일 quality와 동일 source가 끝까지 유지된 metric만
집계한다. CPU, memory, generated traffic, DPU/GPU/bus, produced FPS와 HWC D/C의
provenance가 중간에 바뀌면 하나의 peak로 합치지 않고 N/A다.

HUD graph는 다음 경계에 선을 이어 그리지 않는다.

- source 변경
- quality 변경
- unavailable/read gap
- topology pending `—P`

값이 0인 것과 unavailable을 같은 점으로 그리지 않는다.

## Thermal, memory와 power

- `ActivityManager.MemoryInfo.lowMemory` 또는 memory allocation failure는 active run을
  중단한다.
- thermal CRITICAL 이상은 항상 중단한다.
- optional proactive SEVERE derating은 plan 시작 시 immutable snapshot이며 기본 OFF다.
- Battery Saver가 non-power-save envelope에서 다시 켜지면
  `SAFETY_ENVELOPE_CHANGED`로 중단한다.
- Doze/device-idle은 typed BSP 계약이 없으므로 강제 해제하지 않고 active이면
  거부/중단한다.

이 값들은 performance 결과인 동시에 안전 입력이다.

## Report schema v2

값의 source/quality와 exact/proxy 해석은 이 문서가 소유한다. JSON의 모든 field,
type, nullability, enum, 단위, publication과 consumer 규칙은
[Report schema v2](REPORT_SCHEMA.md)가 authority다.

## 분석 checklist

1. app version, build fingerprint와 scenario ID가 맞는가?
2. terminal event와 cleanup failure가 없는가?
3. exact source/quality가 baseline부터 terminal sample까지 같은가?
4. exact delta와 proxy delta를 구분했는가?
5. typed phase의 DEVICE/CLIENT pair가 fresh하고 distinct한가?
6. producer expected/actual fidelity가 충분한가?
7. GPU/DPU/bus의 source ABI와 unit을 확인했는가?
8. estimated traffic을 measured bus utilization처럼 해석하지 않았는가?
9. thermal, power-save, low-memory 또는 topology recovery pause가 있었는가?
10. provenance가 바뀐 peak/graph 구간을 합치지 않았는가?
